# 10. Ошибки

> Источники: [Спецификация — Defer, Errors, Run-time panics](https://go.dev/ref/spec) · [Пакет errors](https://pkg.go.dev/errors) · [Metanit — глава 10](https://metanit.com/go/tutorial/)

В Go ошибка — обычное значение, последнее среди результатов функции. Её не бросают через весь стек. Вызывающий решает сам: вернуть выше, записать в журнал или попробовать иначе. Один и тот же вид сигнатуры `(T, error)` повторяется от стандартной библиотеки до своего кода.

Тип `error` — интерфейс с одним методом:

```go
type error interface {
    Error() string
}
```

`nil` означает «ошибки нет».

## Как создавать и проверять

```go
func load(id int) (string, error) {
    if id <= 0 {
        return "", fmt.Errorf("некорректный id %d", id)
    }
    return "ok", nil
}

name, err := load(0)
if err != nil {
    return err
}
```

`errors.New` — текст без форматирования. `fmt.Errorf` — текст с подстановками.

Свою ошибку делают структурой с методом `Error() string`, если вызывающему нужны поля, а не только строка: код ответа, идентификатор, временная это ошибка или нет.

## Цепочка

Ошибку нижнего уровня оборачивают, чтобы не потерять причину. Глагол `%w` кладёт исходную ошибку внутрь новой.

```go
if err != nil {
    return fmt.Errorf("чтение пользователя %d: %w", id, err)
}
```

Достать причину:

| Функция | Когда |
|---------|--------|
| `errors.Is(err, target)` | В цепочке есть именно это значение (например, `os.ErrNotExist`) |
| `errors.As(err, &target)` | В цепочке есть ошибка нужного типа, её можно вытащить в `target` |

Сравнивать обёрнутую ошибку через `==` или `err.Error()` не стоит: текст меняется, цепочка — нет.

## defer

`defer` откладывает вызов до выхода из функции: обычный `return`, ошибка или `panic`. Несколько `defer` выполняются в обратном порядке, как стек.

Типичное место — закрыть то, что открыли:

```go
f, err := os.Open(path)
if err != nil {
    return err
}
defer f.Close()
```

Аргументы отложенной функции считаются **сразу**, в момент `defer`, а не в момент вызова. Цикл с `defer` на каждой итерации копит вызовы до конца функции — для файлов в цикле лучше отдельная функция, чтобы закрытие случилось на каждом шаге.

`defer` ещё нужен, чтобы снять мьютекс и поймать `panic` через `recover`.

## panic

`panic` останавливает нормальный ход функции. Отложенные вызовы текущей функции всё равно выполняются, затем паника идёт выше. Если её никто не перехватил, процесс завершается.

`panic` — для ситуаций, которые означают ошибку в программе: нарушен инвариант, невозможная ветка, `nil`, которого не должно быть. Ожидаемые сбои (нет файла, обрыв сети, плохой ввод) возвращают `error`.

## recover

`recover` останавливает панику. Он работает только внутри функции, вызванной через `defer`, и только пока эта паника ещё не ушла из текущей функции.

```go
func safe() (err error) {
    defer func() {
        if v := recover(); v != nil {
            err = fmt.Errorf("panic: %v", v)
        }
    }()
    panic("сбой")
}
```

На границе HTTP-сервера такой перехват не даёт одному запросу уронить процесс. Внутри обычной бизнес-логики `recover` не ставят: ошибку возвращают явно.
