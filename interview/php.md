## Основы языка

### Чем отличаются `==` и `===`?

`==` сравнивает с приведением типов (`1 == "1"` → `true`). `===` — строгое сравнение значения и типа (`1 === "1"` → `false`). На собеседовании обычно ждут: «почти всегда использую `===`».

### Какие типы есть в PHP?

Scalar: `int`, `float`, `string`, `bool`. Составные: `array`, `object`, `callable`, `iterable`. Специальные: `null`, `resource`. В PHP 8+ — union types (`int|string`), `mixed`, `never`, `true`/`false` как standalone types.

### Что такое слабая / сильная типизация в PHP?

PHP — динамически типизированный язык с опциональной строгой типизацией. `declare(strict_types=1);` в файле включает строгую проверку скалярных типов для вызовов функций в этом файле.

### Разница между `echo`, `print`, `print_r`, `var_dump`?

| Конструкция | Назначение |
|-------------|------------|
| `echo` | Вывод, может принимать несколько аргументов, не возвращает значение |
| `print` | Вывод одного выражения, возвращает `1` |
| `print_r` | Человекочитаемый дамп массива/объекта |
| `var_dump` | Тип + значение (для отладки) |

### Области видимости переменных

| Область | Где доступна |
|---------|--------------|
| Локальная | Внутри функции |
| Глобальная | Вне функций; внутри — через `global` или `$GLOBALS` |
| Статическая (`static`) | Сохраняет значение между вызовами функции |
| Суперглобальные | `$_GET`, `$_POST`, `$_SERVER`, `$_SESSION` и др. |

### Чем `include` отличается от `require`?

При ошибке файла: `include` даёт warning и продолжает работу, `require` — fatal error. Варианты `*_once` подключают файл только один раз.

### Что такое ссылки (`&`)?

Ссылка — альтернативное имя той же переменной. `$b = &$a;` — изменение `$b` меняет `$a`. В функциях: передача по ссылке `function f(&$x)`. Объекты в PHP передаются по идентификатору объекта (не полная копия).

## Массивы и строки

### Чем индексированный массив отличается от ассоциативного?

Индексированный — ключи `0, 1, 2…`. Ассоциативный — строковые ключи. В PHP оба — один тип `array` (упорядоченная map).

### Частые функции массивов

`count`, `in_array`, `array_key_exists`, `isset`, `array_merge`, `array_map`, `array_filter`, `array_reduce`, `array_keys`, `array_values`, `usort` / `uasort`, `explode` / `implode`.

Нюанс: `isset($a['k'])` — `false` для `null`; `array_key_exists('k', $a)` — `true`, если ключ есть.

### Как развернуть строку / проверить палиндром?

Классика live coding: цикл, два указателя, или `strrev` (на ASCII; для UTF-8 — осторожно с мультибайтом).

### Разница `mb_*` и обычных строковых функций

`strlen` / `substr` работают с байтами. Для UTF-8 — `mb_strlen`, `mb_substr` и т.д.

## Функции

### Что такое замыкание (closure)?

Анонимная функция, которая может захватывать переменные из внешней области через `use`:

```php
$n = 10;
$fn = function ($x) use ($n) {
    return $x + $n;
};
```

Стрелочные: `fn($x) => $x + $n` — захват по значению автоматически.

### Разница `use` в замыкании и `use` в namespace

В замыкании — захват переменных. В файле с namespace — импорт класса/функции/константы.

### Что такое variadic / splat?

`function sum(int ...$nums)` — произвольное число аргументов. `...$array` — распаковка при вызове.

### Передача по значению и по ссылке

По умолчанию — по значению (копия для скаляров/массивов). `&` — по ссылке. Объекты — по object handle.

## ООП

### Инкапсуляция, наследование, полиморфизм

| Принцип | Суть |
|---------|------|
| Инкапсуляция | Скрытие деталей (`private`/`protected`), публичный интерфейс |
| Наследование | Класс-потомок расширяет родителя (`extends`) |
| Полиморфизм | Один интерфейс — разное поведение (`implements`, переопределение методов) |

### `public` / `protected` / `private`

| Модификатор | Доступ |
|-------------|--------|
| `public` | Везде |
| `protected` | Класс и потомки |
| `private` | Только этот класс |

### `abstract` class vs `interface`

| | Abstract | Interface |
|--|----------|-----------|
| Реализация методов | Может содержать | До PHP 8 — нет; с 8.0 — default methods |
| Свойства | Да | Константы; typed properties в интерфейсах (8.0+) ограничены |
| Множественное | Один `extends` | Много `implements` |
| Назначение | Общая база с частичной реализацией | Контракт поведения |

### Что такое трейт (`trait`)?

Механизм переиспользования кода без наследования. Подключается через `use` внутри класса. При конфликтах имён — `insteadof` / `as`.

### `final` class / method

Запрещает наследование класса или переопределение метода.

### `static` методы и свойства

Принадлежат классу, не экземпляру. Вызов: `ClassName::method()`. `$this` недоступен; есть `self` / `static` (late static binding).

### Late Static Binding (`self` vs `static`)

`self::` — класс, где написан код. `static::` — класс, который вызвали (учёт позднего связывания при наследовании).

### Магические методы (часто спрашивают)

| Метод | Когда |
|-------|-------|
| `__construct` / `__destruct` | Создание / уничтожение |
| `__get` / `__set` / `__isset` / `__unset` | Доступ к недоступным свойствам |
| `__call` / `__callStatic` | Вызов недоступных методов |
| `__toString` | Приведение к строке |
| `__invoke` | Объект как функция |
| `__clone` | После `clone` |
| `__serialize` / `__unserialize` | Сериализация |

### Что такое DI (Dependency Injection)?

Зависимости передаются снаружи (в конструктор/сеттер), а не создаются внутри класса через `new`. Упрощает тестирование и соблюдение DIP (SOLID).

### SOLID — кратко

| Буква | Смысл |
|-------|--------|
| S | Один класс — одна ответственность |
| O | Открыт для расширения, закрыт для изменения |
| L | Потомки взаимозаменяемы с родителем |
| I | Много узких интерфейсов лучше одного толстого |
| D | Зависеть от абстракций, не от конкретики |

## Ошибки и исключения

### `Error` vs `Exception`

Оба реализуют `Throwable`. `Exception` — ожидаемые сбои приложения (ловите в `try/catch`). `Error` — серьёзные проблемы движка (`TypeError`, `ParseError`); ловить можно, но обычно это сигнал бага.

### `try` / `catch` / `finally`

`finally` выполняется всегда (и при `return` из `try`). Несколько `catch` — от частных типов к общим.

### Когда свой exception?

Для доменных ошибок: `UserNotFoundException`, `PaymentFailedException` — чтобы вызывающий код различал причины.

## Работа с данными и HTTP

### PDO vs mysqli

На собеседованиях чаще ждут **PDO**: единый API для разных СУБД, удобные prepared statements, режимы `FETCH_*`.

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE id = ?');
$stmt->execute([$id]);
$user = $stmt->fetch(PDO::FETCH_ASSOC);
```

### Почему prepared statements?

Защита от SQL-инъекций: данные отделены от SQL-шаблона. Не конкатенировать пользовательский ввод в запрос.

### Суперглобальные массивы

`$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `$_SESSION`, `$_SERVER`, `$_FILES`, `$_ENV`.

### Сессии: как работают?

`session_start()` → ID в cookie → данные на сервере (файлы/Redis). Важно: `session_regenerate_id` после логина, не хранить чувствительное без нужды.

### Cookies vs session

Cookie — на клиенте (можно подделать). Session — на сервере, в cookie обычно только ID.

### Как хешировать пароли?

`password_hash($pass, PASSWORD_DEFAULT)` и `password_verify()`. Не MD5/SHA1 «в лоб».

### XSS и CSRF — в двух словах

| Угроза | Защита |
|--------|--------|
| XSS | Экранирование вывода: `htmlspecialchars` |
| CSRF | Токен в форме, SameSite cookie, проверка origin |

### `json_encode` / `json_decode`

`json_decode($s, true)` — ассоциативный массив. Проверять `json_last_error()`. Для API — корректные заголовки `Content-Type: application/json`.

## PHP 8+ (часто спрашивают)

| Тема | Суть |
|------|------|
| Named arguments | `f(name: 'A', id: 1)` |
| Attributes | `#[Route('/')]` вместо docblock-аннотаций |

| Enums | `enum Status { case Active; }` |
| Fibers / readonly / intersection types | По уровню вакансии |
