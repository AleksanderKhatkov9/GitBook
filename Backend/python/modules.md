# 7. Модули и пакеты

> Источники: [Учебник — модули](https://docs.python.org/3/tutorial/modules.html) · [Виртуальные окружения](https://docs.python.org/3/tutorial/venv.html) · [Metanit — глава 6](https://metanit.com/python/tutorial/)

## Модуль

Модуль — это файл `.py`. Имя модуля — имя файла без расширения.

`greetings.py`:

```python
def hello(name):
    return "Привет, " + name
```

`main.py` рядом:

```python
import greetings

print(greetings.hello("Анна"))
```

Другие формы:

```python
from greetings import hello
from greetings import hello as say_hi
```

`import` выполняет модуль один раз и кладёт его в `sys.modules`. Повторный импорт берёт уже загруженный объект.

Импорт с `*` (`from greetings import *`) тащит все публичные имена и перекрывает локальные. В коде программы его избегают: непонятно, откуда взялось имя.

## Запуск как программа

У модуля есть имя `__name__`. Если файл запустили напрямую, оно равно `"__main__"`. Если его импортировали — равно имени модуля.

```python
def main():
    print("запуск")

if __name__ == "__main__":
    main()
```

Код под этой проверкой не выполнится при `import`. Функции модуля при этом остаются доступны.

## Где ищут модуль

Интерпретатор смотрит каталог скрипта, затем записи в `PYTHONPATH`, затем каталог стандартной библиотеки. Фактический список — `sys.path`.

После первого импорта CPython может положить рядом байткод в `__pycache__/*.pyc`. Это кэш, его не редактируют и обычно не коммитят. Исходный `.py` остаётся тем, что вы правите.

## Пакет

Пакет — каталог с модулями. Файл `__init__.py` помечает каталог как обычный пакет и даёт место для общей инициализации. Без этого файла каталог может стать пакетом пространства имён (PEP 420): он собирается из нескольких путей, и своего `__init__` у него нет. В коде проекта проще держать явный `__init__.py`.

```text
app/
  __init__.py
  users.py
  orders.py
```

```python
from app.users import User
import app.orders as orders
```

## Часть стандартной библиотеки

| Модуль | Зачем |
|--------|--------|
| `math` | `sqrt`, `floor`, константа `pi` |
| `random` | Случайные числа для игр и тестов, не для секретов |
| `secrets` | Токены и пароли: криптостойкий генератор |
| `decimal` | Десятичные деньги без двоичной ошибки `float` |
| `dataclasses` | Класс с готовыми `__init__`, `__repr__`, `__eq__` |
| `pathlib` | Пути к файлам объектами, а не склейкой строк |

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
```

`random` предсказуем, если задать `random.seed`. Для ключей и сессий берут `secrets.token_hex()`.

## pip и виртуальное окружение

Пакеты ставят **в окружение проекта**, не в системный Python. Иначе версии библиотек разных проектов перемешаются.

```bash
python -m venv .venv
```

Windows, активация в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install requests
```

macOS и Linux: `source .venv/bin/activate`.

| Команда | Что делает |
|---------|------------|
| `python -m pip install имя` | Поставить пакет с PyPI |
| `python -m pip install -r requirements.txt` | Поставить список зависимостей |
| `python -m pip freeze` | Показать установленное с версиями |

Вызов через `python -m pip` привязан к тому интерпретатору, которым вы пользуетесь. Голый `pip` иногда указывает на другой Python.

[uv](https://docs.astral.sh/uv/) — отдельный менеджер окружений и пакетов. Он быстрее вызывает тот же PyPI, но это уже внешний инструмент, не часть стандартной библиотеки.
