# 9. Горутины

> Источники: [Спецификация — Go statements, Channel types, Select](https://go.dev/ref/spec) · [Пакет sync](https://pkg.go.dev/sync) · [Metanit — глава 9](https://metanit.com/go/tutorial/)

Горутина — функция, которая выполняется одновременно с остальными. Запускает её ключевое слово `go`. Планировщик языка сажает многие горутины на меньшее число потоков ОС. Это не системный поток и не обещание, что кусок кода пойдёт на отдельном ядре прямо сейчас.

```go
go fmt.Println("рядом")
fmt.Println("здесь")
```

Программа заканчивается, когда заканчивается `main`, даже если горутины ещё работают. Их нужно дождаться или остановить явно.

## WaitGroup

`sync.WaitGroup` считает, сколько задач ещё не завершилось.

```go
var wg sync.WaitGroup

wg.Add(1)
go func() {
    defer wg.Done()
    fmt.Println("задача")
}()

wg.Wait()
```

`Add` вызывают **до** запуска горутины. `Done` ставят через `defer`, чтобы счётчик уменьшился и при выходе по ошибке. В функцию передают указатель `&wg`: копия группы не связана с оригиналом. В примере выше замыкание видит переменную `wg` напрямую — так тоже можно, пока группа не копируется присваиванием.

## Каналы

Канал передаёт значения между горутинами. Создают его через `make`.

```go
messages := make(chan string) // без буфера: отправитель ждёт получателя

go func() {
    messages <- "готово"
}()

msg := <-messages
fmt.Println(msg)
```

| Вид | Поведение |
|-----|-----------|
| `make(chan T)` | Вместимость 0. Отправка ждёт приём, приём ждёт отправку |
| `make(chan T, n)` | Буфер на `n` значений. Отправка блокируется, только когда буфер полон |

Отправка в канал, у которого нет получателя и нет места в буфере, блокирует горутину. Если ждать уже некому, это взаимная блокировка, и рантайм останавливает программу.

Закрытие сообщает: значений больше не будет. Закрывает **отправитель**. Приём из закрытого канала сразу отдаёт нулевое значение. Второе значение `ok` отличает «пришло значение» от «канал закрыт».

```go
close(messages)

v, ok := <-messages
if !ok {
    fmt.Println("закрыт")
}

for v := range jobs { // range читает, пока канал не закроют
    fmt.Println(v)
}
```

Отправка в закрытый канал и повторное `close` — `panic`.

## Направление

В параметре канал сужают до отправки или до приёма. Компилятор тогда не даст перепутать сторону.

```go
func produce(out chan<- int) { out <- 1 }
func consume(in <-chan int)  { fmt.Println(<-in) }
```

## select

`select` ждёт несколько операций с каналами. Срабатывает один готовый вариант. Если готовы несколько — выбор случайный.

```go
select {
case msg := <-messages:
    fmt.Println(msg)
case <-time.After(time.Second):
    fmt.Println("таймаут")
default:
    fmt.Println("прямо сейчас никто не готов")
}
```

`default` делает выбор неблокирующим. Без него `select` ждёт. `time.After` удобен как таймер на одну попытку; в цикле для этого лучше `time.NewTimer` или `context.WithTimeout`, иначе на каждой итерации остаётся лишний таймер.

Каналом же передают не только данные, но и сигнал «можно продолжать»: пустая структура `struct{}` ничего не весит, а факт приёма уже является событием.

## Гонка данных

Гонка — когда несколько горутин обращаются к одной переменной и хотя бы одна пишет, без согласования. Результат тогда не определён.

Проверка при тестах и запуске:

```bash
go test -race ./...
go run -race .
```

Детектор находит гонки на исполненном пути. Он не доказывает, что гонок нет в коде, который этот запуск не трогал.

## Мьютекс

Если горутины делят одну структуру, доступ закрывают `sync.Mutex`.

```go
var (
    mu    sync.Mutex
    total int
)

mu.Lock()
total++
mu.Unlock()
```

`Unlock` ставьте через `defer` сразу после `Lock`, чтобы блокировка снялась при любом выходе. `sync.RWMutex` пускает много одновременных читателей и одного писателя.

Канал и мьютекс решают разное. Канал передаёт владение значением дальше по цепочке. Мьютекс охраняет кусок памяти, который остаётся на месте. Для счётчика и кэша чаще мьютекс. Для очереди задач чаще канал.
