# 14. Рефлексия

> Источники: [Пакет reflect](https://pkg.go.dev/reflect) · [Спецификация — Type identity, Method sets](https://go.dev/ref/spec) · [Metanit — глава 14](https://metanit.com/go/tutorial/) · [Laws of Reflection](https://go.dev/blog/laws-of-reflection)

Рефлексия разбирает тип и значение **во время выполнения**: имя типа, поля структуры, теги, динамический тип внутри интерфейса.

```go
n := 10
t := reflect.TypeOf(n)
v := reflect.ValueOf(n)
fmt.Println(t.Kind(), v.Int()) // int 10
```

`Type` описывает тип. `Value` — само значение, с ним можно читать поля и вызывать методы. `Kind` — грубая категория: `Int`, `String`, `Struct`, `Slice`, `Ptr`, `Map`, а не имя вашей структуры.

Поля структуры и теги:

```go
type User struct {
    Name string `json:"name"`
}

u := User{Name: "Анна"}
f := reflect.TypeOf(u).Field(0)
fmt.Println(f.Tag.Get("json")) // name
```

Пакет `encoding/json` так и работает: смотрит теги `json` и сопоставляет поля. Свой разбор конфигов и протокол часто проще опереть на готовый `json` или `xml`, чем писать обход через `reflect`.

## Когда она уместна

| Уместна | Не нужна |
|---------|----------|
| Библиотека сериализации, ORM, маршрутизатор | Обычная бизнес-логика |
| Вызов метода, имя которого пришло извне | Вызов, который известен при компиляции |
| Общий код над чужими структурами | Код, где тип и так ваш |

Рефлексия обходит проверку типов компилятором. Ошибки всплывают при запуске. Вызовы медленнее обычных. Читать такой код труднее.

Три правила из [Laws of Reflection](https://go.dev/blog/laws-of-reflection):

1. Из интерфейса рефлексия достаёт конкретное значение: `reflect.ValueOf`.
2. Из значения рефлексии можно снова получить интерфейс: `Value.Interface`.
3. Чтобы изменить значение, оно должно быть **адресуемым**. `ValueOf` от копии менять нельзя. Берут указатель и доходят до элемента через `Elem()`. `CanSet()` показывает, разрешена ли запись.

```go
x := 10
v := reflect.ValueOf(&x).Elem()
if v.CanSet() {
    v.SetInt(20)
}
```

В прикладном коде, если тип известен, утверждение типа и обычный метод короче и безопаснее рефлексии. К `reflect` переходят, когда набор типов заранее не закрыт и его нельзя выразить интерфейсом.
