# 4. Указатели

> Источники: [Спецификация — Pointer types, Address operators](https://go.dev/ref/spec) · [Metanit — глава 4](https://metanit.com/go/tutorial/)

Указатель хранит **адрес** значения в памяти. Тип «указатель на T» записывается `*T`.

```go
n := 10
p := &n   // p имеет тип *int, в нём адрес n
fmt.Println(*p) // 10 — значение по адресу
*p = 15
fmt.Println(n)  // 15
```

| Запись | Смысл |
|--------|--------|
| `&x` | Адрес переменной `x` |
| `*T` | Тип: указатель на `T` |
| `*p` | Значение, которое лежит по адресу в `p` |

Арифметики указателей нет: сдвинуть `p` на «следующую ячейку» нельзя. Так меньше шансов испортить чужую память. Обход последовательности делают срезом или массивом.

## nil

Нулевое значение указателя — `nil`: адреса нет. Разыменование `nil` останавливает программу (`panic`).

```go
var p *int
if p != nil {
    fmt.Println(*p)
}
```

`new(T)` выделяет память под `T`, заполняет её нулём и возвращает `*T`.

```go
p := new(int)
*p = 7
```

Для структур чаще пишут составной литерал `&User{Name: "Анна"}` — он и создаёт значение, и сразу берёт адрес.

## Указатели и функции

Аргумент всегда копируется. Копия числа не связана с оригиналом. Копия указателя ведёт на **ту же** переменную.

```go
func bump(n *int) {
    *n++
}

x := 1
bump(&x)
fmt.Println(x) // 2
```

Когда передавать указатель:

| Ситуация | Что передавать |
|----------|----------------|
| Функция должна изменить переменную вызывающего | Указатель |
| Значение большое, копировать его на каждый вызов дорого | Указатель |
| Значение маленькое и менять его не нужно | Само значение |

Указатель на локальную переменную можно вернуть из функции. Сборщик мусора не даст этой памяти исчезнуть, пока на неё есть ссылки. Следить за «жива ли переменная на стеке» не нужно — компилятор сам решает, где её разместить.
